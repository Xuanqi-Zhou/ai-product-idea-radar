## 一、开发工具推荐

### myco-ai/myco
- **核心亮点**：多台电脑和手机共用你已付费的 AI agent
- **亮点关键词**：多 agent 并行、跨设备接管、定时调度、自托管
- **复用方向**：值得借鉴的是把已付费的 Claude Code、Codex 等命令行 agent 统一接入一个跨设备入口，让同一批 agent 在 Mac、Windows、Linux 和 iPhone 上被同时调度和接管。
- **最小 MVP**：第一版先做一个本机常驻进程，把 Claude Code 和 Codex 的会话注册进来，支持同时启动两个任务，并从手机浏览器查看进度、追加指令。
- **标签**：开发者工具、工作流自动化、桌面工作台
- 来源：GitHub｜[查看原文](https://github.com/myco-ai/myco)

### skyfireitdiy/Jarvis
- **核心亮点**：多智能体分工操控电脑与浏览器
- **亮点关键词**：多 Agent 协作、操控本机、网页浏览、Python 框架
- **复用方向**：把「多个智能体分工、各自负责一段任务并直接操作本机与浏览器」的编排方式，迁移到需要跨软件连续执行任务的自动化助手场景。
- **最小 MVP**：第一版先只接两个 agent：一个把用户任务拆成步骤，另一个调用鼠标键盘和浏览器完成每一步，先跑通一条真实的跨软件操作任务。
- **标签**：工作流自动化、多 Agent 协作
- 来源：GitHub｜[查看原文](https://github.com/skyfireitdiy/Jarvis)

### Hub

## 四、Idea

### 法律 AI 工作流
- **需求**：法务和律师要把合同审查、文书生成这类重复性法律工作交给 AI，但通用模型给出的结论颗粒度太粗，不敢直接采用。
- **现状**：目前多是把通用大模型和 Ironclad、律己 AI、幂律智能等现成工具混用，或用 LangChain Agent 接法律数据库自建流程，讨论焦点仍停留在“AI 能不能审得准”。
- **方向跟踪**：值得跟踪的是把公开法律条文与裁判文书做成可检索底座，让模型针对具体条款输出带引用出处、可逐条核对的判断，而非只给笼统修改建议。
- **来源**：https://www.zhihu.com/question/606923806/answer/3392966630、https://zhuanlan.zhihu.com/p/702780746

### AI 应用场景 / 数据
- **需求**：B端产品经理在梳理多组织、多角色、多系统的全场景需求时，需要人工逐一确认组织架构、角色权限、单据流转和跨系统流程，既耗时又容易遗漏。
- **现状**：目前主要靠人工访谈各角色，再用 Xmind 画结构图、流程图和架构图来对齐业务、研发、测试与 UI，并先判断产品是标准化还是定制化，再决定梳理路径。
- **方向跟踪**：值得跟踪的是从访谈记录和组织架构信息中自动抽取角色、流程、单据与权限关系，并生成可校验的结构图、流程图和架构图的需求梳理辅助工具。
- **来源**：https://www.zhihu.com/question/460427762/answer/1895672636、https://zhuanlan.zhihu.com/p/609160954

### 供应链分析 Agent
- **需求**：做补货与库存决策时，业务人员要在 Excel 里反复拆解需求预测、安全库存和外部约束，缺少能快速生成并比选补货方案的助手。
- **现状**：实际工作中普遍用 JIT 叠加安全库存、按库存周转天数反推补货量，工具侧主要靠 Excel、VBA、PowerQuery 做预测和库存管理，少数场景才用 Eviews 或 Supply chain guru 做预测与仿真。
- **方向跟踪**：值得跟踪的是让决策型 Agent 承接“把经验和外部约束显式化为可调参数”这一步，在补货场景里做约束增删与方案比选，而不是再复刻一套库存理论模型。
- **来源**：https://zhuanlan.zhihu.com/p/342366466、https://zhuanlan.zhihu.com/p/693627895
