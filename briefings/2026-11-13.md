## 一、开发工具推荐

### pingdotgg/t3code
- **核心亮点**：用手机接管本机编码 Agent
- **亮点关键词**：远程接管、跨设备会话、多 Agent 切换
- **复用方向**：把跑在本机的编码 Agent 封装成可远程接入的持久会话，让手机或另一台电脑接进同一个会话，继续查看输出、发送指令并中断任务；这套机制可以迁移到任何需要长时间挂机的命令行 Agent 场景。
- **最小 MVP**：第一版只做单机会话托管加一个移动端网页控制页，能在手机上看到 Agent 实时输出、发送新指令、中断当前任务这三件事即可跑通。
- **标签**：开发者工具、工作流自动化
- 来源：GitHub｜[查看原文](https://github.com/pingdotgg/t3code)

### vercel-labs/agent-desktop
- **核心亮点**：用命令行让 AI 操作 macOS 桌面
- **亮点关键词**：CLI 控制桌面、无障碍 API、MCP 接入
- **复用方向**：可以借鉴它通过系统无障碍 API 而不是截图识别来暴露桌面控件的方式，把这种能力封装成可接入的 MCP 工具，让现有 AI 代理直接操作本机应用。
- **最小 MVP**：先实现一个 Rust CLI，用 macOS 无障碍 API 枚举前台窗口的按钮和输入框，并支持按名称点击或填值，跑通读取界面和操作界面这条最小链路。
- **标签**：开发者工具、工作流自动化、桌面工作台
- 来源：GitHub｜[查看原文](https://github.com/vercel-labs/agent-desktop)

## 四、Idea

### 法律 AI 工作流
- **需求**：法务和律师要把合同审查、文书生成这类重复性法律工作交给 AI，但通用模型给出的结论颗粒度太粗，不敢直接采用。
- **现状**：目前多是把通用大模型和 Ironclad、律己 AI、幂律智能等现成工具混用，或用 LangChain Agent 接法律数据库自建流程，讨论焦点仍停留在“AI 能不能审得准”。
- **方向跟踪**：值得跟踪的是把公开法律条文与裁判文书做成可检索底座，让模型针对具体条款输出带引用出处、可逐条核对的判断，而非只给笼统修改建议。
- **来源**：https://www.zhihu.com/question/606923806/answer/3392966630、https://zhuanlan.zhihu.com/p/702780746

### 语言 AI 陪练
- **需求**：学了多年英语的人仍卡在无法连续流利说出一整段话，真正缺的是能针对整段开口输出、把错误指到具体音节的练习场景。
- **现状**：目前主要靠开源 Enjoy 这类工具做 AI 跟读评分、上传美剧视频自动切字幕逐句跟练，或用 ielts-buddy 把口语陪练塞进本地 Agent，讨论焦点集中在怎样才能拿到“具体哪里说错了”的反馈。
- **方向跟踪**：值得跟踪的是让用户自带美剧或自录文本自动切成可跟练单元、并把纠错落到音节级反馈的练习闭环，而不是再加一层通用口语打分。
- **来源**：https://www.zhihu.com/question/641065475/answer/3415615067、https://zhuanlan.zhihu.com/p/2003831453235036734

### 简历优化助手
- **需求**：求职者需要在简历里把经历写得更完整、更贴岗位，同时避免为了好看而夸大时间线或学历，最后在背景调查时出问题。
- **现状**：现在大家主要用职徒简历、五百丁、乔布简历这类网页工具做智能排版、一键压缩到一页和导入导出，但讨论集中在导出收费和模板实用性；另一条线是在知乎交流经历合并、学历口径等灰色做法及其背调风险。
- **方向跟踪**：值得继续跟踪的是把真实性校验内置到简历编辑流程中：对时间线断档、经历合并、学历口径做一致性检查并提示背调风险，同时给出合规替代表达和面试追问预案；而不是只再加一套模板。
- **来源**：https://www.zhihu.com/question/561449133/answer/1983922060662182747、https://www.zhihu.com/question/306288054/answer/673021709
