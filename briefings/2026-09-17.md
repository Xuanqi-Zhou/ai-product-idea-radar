## 四、Idea

### 智能旅行助手
- **需求**：自由行用户做行程规划时，攻略散落在马蜂窝、小红书、知乎、抖音等多个平台，必须靠人工筛选拼接才能得到一份可执行的行程方案。
- **现状**：目前主流做法是以马蜂窝、穷游等作基础攻略源，再用小红书、知乎、抖音补细节，凭个人经验挑选拼接；也有开发者在 GitHub 上尝试把「规划→小红书调研→交互式地图」封装成 Agent 技能。
- **方向跟踪**：值得继续跟踪的是把小红书这类种草平台的非结构化攻略检索、行程草案自动生成与交互式地图展示打通成一条自动化流水线，而不是再做一个攻略信息聚合应用。
- **来源**：https://www.zhihu.com/question/29685173/answer/87246075、https://www.zhihu.com/question/578463082/answer/2851939264

### 邮件自动化工具
- **需求**：外贸业务员在客户长时间不回复时，需要基于该客户的历史往来写出下一封得体的英文跟进邮件，而不是继续套用群发模板。
- **现状**：现在主要有两路解法：一体化 AI 外贸邮箱客户端把英文回复、客户洞察和跟进管理打包解决，而以“替你处理邮件”为卖点的邮件代理在 Product Hunt 上拿到 263 票，说明整包式邮件代理解法正被真实用户投票验证。
- **方向跟踪**：值得继续跟踪的是让 agent 同时持有客户上下文、跟进节奏和英文措辞三件事，并自行判断这封该不该发、什么时候发，以及把收件箱和可搜索线程当作 agent 异步协作底层状态的做法，看能否把跟进从写作问题变成调度问题。
- **来源**：https://www.zhihu.com/question/302778956/answer/1992189899495999011、https://www.zhihu.com/question/2029879302720832806/answer/2064206354961667970

### 供应链分析 Agent
- **需求**：中小企业需要把历史订单和库存数据转成可执行的补货建议，但预测、仿真与最终决策彼此割裂。
- **现状**：目前中小企业的做法是Excel加PowerQuery/Pivot管需求预测和库存订单、用Eviews/SPSS/SAS做统计预测，仿真和战略规划另找Flexsim、Supply Chain Guru，讨论集中在工具清单与建模步骤上，最终补货决策仍由人凭经验拍板。
- **方向跟踪**：值得跟踪的是能基于历史订单做匹配推理、输出补货建议并同时给出依据与场景对比的可解释决策Agent，重点在于把预测结论到补货动作这一段接上，而不是再堆一个工具清单或数据看板。
- **来源**：https://zhuanlan.zhihu.com/p/342366466、https://zhuanlan.zhihu.com/p/693627895
