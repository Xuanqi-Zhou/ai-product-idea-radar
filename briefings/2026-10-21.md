## 一、开发工具推荐

### vibheksoni/stealth-browser-mcp
- **核心亮点**：让 agent 用上不被反爬阻断的浏览器
- **亮点关键词**：反检测浏览器、CDP 直连、网络请求拦截、像素级 UI 克隆
- **复用方向**：值得借鉴的是把隐身浏览器（反检测、可绕 Cloudflare）连同导航、网络钩子、DOM 抽取一起封装成 MCP 工具，让 agent 能直接抓取或复刻被反爬保护的网页。
- **最小 MVP**：第一版只做 MCP server 加两个工具：navigate 和 extract_dom，底层用 nodriver 启动隐身 Chrome，跑通“给一个 URL 返回结构化 DOM”的最小链路。
- **标签**：开发者工具、工作流自动化、浏览器自动化
- 来源：GitHub｜[查看原文](https://github.com/vibheksoni/stealth-browser-mcp)

### skalesapp/skales
- **核心亮点**：说个目标，Agent 自己写码、控桌面
- **亮点关键词**：跨端自主任务、桌面与浏览器操作、免 Docker 免终端、Agent Skills
- **复用方向**：把「设目标后自主排期执行」的 Agent 任务循环，做成不需要 Docker 和终端、普通用户直接安装就能用的桌面应用，这个形态值得迁移到自己的 Agent 产品里。
- **最小 MVP**：第一版只做 macOS 单端：用户填一个定时目标，Agent 调用本地 Ollama 或一家 BYOK 模型完成浏览器操作并回传结果，先不做多端同步和 Agent 团队。
- **标签**：开发者工具、工作流自动化、浏览器自动化
- 来源：GitHub｜[查看原文](https://github.com/skalesapp/skales)

### Navige
- **热度**：🔥PH 248票｜48评
- **核心亮点**：拦住 AI agent 跑飞的账单
- **亮点关键词**：预算上限、模型路由、缓存复用、死循环检测
- **复用方向**：把预算上限、模型路由和缓存组合成 agent 运行时的成本闸门，这套做法可以迁移到任何按 token 计费的 LLM 应用里。
- **最小 MVP**：第一版先给单次 agent 运行设成本上限并检测死循环，超预算就中断，同时回传触发中断的具体步骤和原因。
- **标签**：开发者工具
- 来源：Product Hunt｜[查看原文](https://www.producthunt.com/products/navige?utm_campaign=producthunt-api&utm_medium=api-v2&utm_source=Application%3A+ai-idea-radar-v4-2+%28ID%3A+294543%29)

## 四、Idea

### AI 应用场景 / 数据
- **需求**：B端产品经理在梳理业务全场景时，最耗神的是要把角色、单据、业务流程、数据传递等要素完整拆出并落到需求文档，手工做慢且担心遗漏。
- **现状**：当下讨论集中在用流程模板和个人方法论来兜底，很多人按标准产品/定制产品分类，再通过梳理组织架构、分角色访谈和整理业务流程来产出需求。
- **方向跟踪**：值得跟踪把角色-单据-流程-数据传递等梳理结构做成的半自动场景建模辅助，让产品经理以结构化输入快速生成全场景需求清单。
- **来源**：https://zhuanlan.zhihu.com/p/20468570、https://www.zhihu.com/question/460427762/answer/1895672636

### 简历优化助手
- **需求**：求职者写简历时不知道怎么把自己的经历写得更贴合目标岗位，也不确定排版和措辞是否专业。
- **现状**：现在大家主要用职徒简历、五百丁、乔布简历、二三简历等在线工具一键排版和自动生成，讨论中常提到导出强制收费、模板花哨、英文翻译和邮件投递等附加功能。
- **方向跟踪**：值得继续跟踪的方向，是基于目标岗位 JD 解析经历、改写表述，并把简历优化与投递、模拟面试衔接起来；GitHub 上 Boss-Claw 的简历解析到按岗定制、JobPilot 的 JD 匹配都属于这个方向。
- **来源**：https://www.zhihu.com/question/306288054/answer/673021709、https://zhuanlan.zhihu.com/p/2020928851677586562

### 法律 AI 工作流
- **需求**：律师和当事人在合同签字前，需要一份能具体对应到条款的审核结果：先补齐交易模式与背景，再逐条识别风险，而非扫一遍合同就下结论。
- **现状**：现状是当事人直接签网上漏洞百出的模板，或把合同随手丢给律师“看一眼”，律师在信息不全下反复追问背景、按流程逐条核对，耗时从半小时拖到几天；LexAI、GLM-Legal 等已把合同审查、文书生成、法规检索打包成 LLM 平台。
- **方向跟踪**：值得跟踪的是把审前信息采集前置为审查流程第一步：用结构化问答锁定交易模式与背景，再把风险结论与修改建议对应到具体条款，而非只输出一份通用审查清单。
- **来源**：https://zhuanlan.zhihu.com/p/702780746、https://www.zhihu.com/question/530439453/answer/2471635526
