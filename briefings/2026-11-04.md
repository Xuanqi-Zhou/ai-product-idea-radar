## 一、开发工具推荐

### JetBrains/thinkrail
- **核心亮点**：随你工作方式自我重塑的轻量 IDE
- **亮点关键词**：轻量 IDE、界面自定制、pi agent、spec 驱动编码
- **复用方向**：值得借鉴的是把 agent 技能包和 spec-driven 编码流程直接嵌进编辑器本体，并让 IDE 布局按用户实际操作习惯自动改造，而不是把 AI 挂在编辑器旁边的侧边栏里。
- **最小 MVP**：第一版先做一个只支持单一语言的最小编辑器外壳，接入 pi agent 跑通「写 spec → 生成代码 → 在编辑器内确认」这一条链路，再记录用户操作习惯去自动调整一次界面布局。
- **标签**：开发者工具、工作流自动化
- 来源：GitHub｜[查看原文](https://github.com/JetBrains/thinkrail)

### AgentKit by Scalekit
- **热度**：🔥PH 360票｜86评

- **亮点关键词**：MCP 网关、代用户授权、权限范围、认证托管

## 四、Idea

### 法律 AI 工作流
- **需求**：法务和律师要把合同审查、文书生成这类重复性法律工作交给 AI，但通用模型给出的结论颗粒度太粗，不敢直接采用。
- **现状**：目前多是把通用大模型和 Ironclad、律己 AI、幂律智能等现成工具混用，或用 LangChain Agent 接法律数据库自建流程，讨论焦点仍停留在“AI 能不能审得准”。
- **方向跟踪**：值得跟踪的是把公开法律条文与裁判文书做成可检索底座，让模型针对具体条款输出带引用出处、可逐条核对的判断，而非只给笼统修改建议。
- **来源**：https://www.zhihu.com/question/606923806/answer/3392966630、https://zhuanlan.zhihu.com/p/702780746

### 语言 AI 陪练
- **需求**：学多年英语的人仍卡在无法连续说满一段话，缺少能围绕具体话题说满一段、被指出卡点后重说的陪练，而非单词跟读。
- **现状**：家长侧用词典笔把跟读评分、音素级发音指导和口语陪练嵌入查词背词动线；备考侧在 GitHub 用 ielts-buddy 等本地 Agent 技能，把口语陪练接入学习计划、作文批改与模考复盘。
- **方向跟踪**：值得跟踪的是把连续表达一段话做成可评分、可回放、可重说的训练单元，记录卡顿与用词并给出下一轮重说的具体修改项，而非停留在单句打分。
- **来源**：https://zhuanlan.zhihu.com/p/2041953993723737149、https://www.zhihu.com/question/641065475/answer/3415615067

### 教育 AI 辅导
- **需求**：教师需要把备课、课堂提问、课后反思连贯成一条可复用的辅导流程，但现有做法多靠人工经验拼接，难以持续迭代。
- **现状**：大家主要用经验帖总结的“定计划—拆知识点—设问巩固—课后记录反思”流程，配合教育资源平台、课件模板和微课工具手工拼装，AI 仅顺带承担资源推送。
- **方向跟踪**：把知识点切分、设问与巩固设计和课后反思回流串成可迭代的备课链路，让课堂上生成的学生问题与反应自动成为下一轮备课输入。
- **来源**：https://zhuanlan.zhihu.com/p/5875025118、https://www.zhihu.com/question/22281218/answer/1244497920
